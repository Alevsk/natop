# nats-tui Implementation Plan

> Execute inline with the executing-plans skill. The user approved autonomous
> implementation, so proceed through all verification without approval checkpoints.

**Goal:** Deliver a standalone Go terminal dashboard for multiple NATS deployments,
with live JetStream metadata and convenient Makefile commands.

**Architecture:** Configuration resolves named connection settings. Independent
workers fetch stream and consumer metadata and send immutable snapshots to a
single UI event loop. A thin executable owns flags, signal handling, and shutdown.

**Tech stack:** Go 1.26, official nats.go JetStream API, tview/tcell, standard JSON.

## Tasks

- [x] Configuration (`internal/config/config.go`, `config_test.go`): test explicit
  CLI precedence, invalid durations, duplicate names, auth conflicts, environment
  references, and secret redaction; implement strict JSON loading and defaults.
  Verify with `rtk go test ./internal/config`.
- [x] Monitoring (`internal/monitor/{types,client,manager,demo}.go`, tests): verify
  with disposable embedded JetStream servers: stream/consumer statistics,
  unchanged consumer state, stale data, empty results, and failed peer independence.
  Fetch metadata with bounded contexts, retain old data on errors,
  and deliver independently refreshed snapshots. Verify with
  `rtk go test -race ./internal/monitor`.
- [x] Terminal UI (`internal/ui/{ui,table,details}.go`, `ui_test.go`): test keyboard
  navigation/filtering, identical stream names across connections, selection
  stability, stale status, and shutdown using a simulation screen.
  Implement stream, consumer, connection, and details views with help and sorting.
  Verify with `rtk go test -race ./internal/ui`.
- [x] Executable and packaging (`main.go`, `Makefile`, `Dockerfile`,
  `compose.yaml`, `examples/connections.json`, `.gitignore`, `.dockerignore`):
  expose server/config/refresh/demo/version flags; handle signals and cleanup;
  add `help`, `build`, `run`, `demo`, `test`, `vet`, `check`, `fmt`, `build-linux`,
  `docker-build`, `docker-run`, `docker-demo`, `docker-multi`, and `clean` targets.
  Build CGO-free release executables with version injection. Use a certificate-
  equipped minimal runtime image and both user-provided external Docker networks.
- [x] README: document keys, exact make commands, authentication and configuration
  precedence, Docker networks/published ports, read-only behavior, pending metrics,
  stale data and limitations; explain local demo vs real NATS operation.
- [x] Final verification: run `rtk proxy make check`, native/Linux builds, version/help,
  PTY demo interactions, Docker image build/demo and two-network integration with
  disposable infrastructure. Review final implementation against the spec, fix
  findings, rerun affected checks, and record actual binary sizes.

## Review checklist

Every configured connection must remain visible when another fails. Stale or
partial data must be labeled and successful empty lists must clear old resources.
No monitor operation consumes/acks application messages. Names and diagnostics
must not inject terminal control sequences or expose credentials. The Docker
examples must join existing networks without changing the user's NATS services.

## Delivered and verified

The user requested prioritizing the working tool over broader test coverage.
Kept focused configuration, monitor, and UI tests; `make check` passes with the
race detector. Native macOS arm64 and static Linux amd64 builds pass, as do
Docker builds, interactive native/demo checks, and `make docker-multi` against
two disposable networks containing independent JetStream servers. The interactive
checks exercised stream/consumer/connection views, details, filtering, help,
and normal quit. Native and Linux binaries are approximately 7.3 and 7.8 MiB.

The current NATS client does not expose lost-message counts; that column displays
an explicit unknown marker, documented in the README and in-app help. The real
remote cloud deployments were not accessed; the supplied Docker configuration
uses the network and hostname values from the request.
